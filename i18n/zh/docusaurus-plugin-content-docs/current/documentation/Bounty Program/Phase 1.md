# 第一期漏洞赏金

**第一期**是 TTSWAP 首个公测赏金季：真实资金在协议内、三轨奖励、GitHub 负责任披露 。

> 合约地址、日历等占位符以 `{{...}}` 标出，以正式公告为准；若与本页冲突，以最新公告为准。

## 1. 目标

1. 在**封顶、分批**的资金敞口下（计划约 **4,000 USDT**、四批注入）尽早挖出抽干资金类与关键逻辑漏洞。  
2. 坚持 **先链上证明（轨 A），再完整披露归档（轨 B）**。  
3. 攻击成功者拿 **靶场即时结算 + 上线后 TTS**；其它有效报告走 **按等级空投（轨 C）**。

披露规范参考 Immunefi 等习惯；执行方式为 **自托管协议内靶场 + GitHub Issues**。

### 2.2 靶场本金（合计约 4,000 USDT，分批）

部署后，TTSWAP 向协议注入**可攻击靶场**（USDT 和/或 **等值主流币**如 ETH / WBTC，计价口径见当期公告），用于验证能否被非授权抽出 / 铸出 / 挪用。

### 2.3 注资节奏

| 批次 | 时间点 | 注入金额 | 累计计划 |
|:--|:--|:--|:--|
| 1 | 公测部署完成后 | **1,000 USDT**（或等值） | 1,000 |
| 2 | 自第 1 批起约 **+3 周** | **1,000 USDT**（或等值） | 2,000 |
| 3 | 自第 2 批起约 **+3 周** | **1,000 USDT**（或等值） | 3,000 |
| 4 | 自第 3 批起约 **+3 周** | **1,000 USDT**（或等值） | **4,000** |

- **计划靶场本金合计：4,000 USDT（或等值）。** 链上实时余额 = 已注入 − 轨 A 结算 / 抽出。  
- 若靶场被抽干或需热修重部署，可用**剩余计划额度**或公告补注预算继续后续批次（日期可顺延）。  
- **轨 A** 只按**确认时链上剩余**结算 — **不得预支**尚未注入的批次。  
- 注资交易与余额应可在 Etherscan 核验；官方会更新已注入 / 剩余 / 下一批预计时间。

## 3. 三轨奖励

**一句话：** 轨 B 是 **轨 A 成功者的追加奖**。只攻击不披露 → 只有轨 A。有效 Issue 但未打成轨 A → 轨 C。

```text
轨 A 成功 ──► 靶场结算（≤ 当时链上剩余；计划总额 4,000U）
       │
       └─ + 合规 GitHub Issue（PoC + 钱包） ──► 轨 B：上线后约 1,000U 等值 TTS

未达成轨 A，但 Issue 有效 ──► 轨 C：按等级 TTS 空投
```

### 3.1 轨 A · 链上攻击成功（即时 / 靶场结算）

| 条件 | 奖励 |
|:--|:--|
| 在本期部署上完成可验证的未授权抽出、铸造或靶场不可恢复损失 | 按可量化损失 / 抽出金额结算，**上限为当时靶场剩余** |
| 提供交易哈希与路径，配合确认 | 官方确认后结算；自导自演 / 刷量无效 |

轨 A 来自分批注入的约 **4,000 USDT** 靶场。池空且下一批未到账时，轨 A 暂停至补注 / 重部署。若要轨 B，须完成 §3.2 与 §6。

### 3.2 轨 B · 轨 A 成功者的披露追加奖（约 1,000 USDT 等值 TTS）

**前提：** 已获官方 **轨 A** 确认。然后：

1. 在计划仓库开 Issue（见下方模板），写明轨 A 交易哈希；  
2. 完整复现 / PoC，便于官方或第三方独立复现；  
3. 留下接收空投的 EVM 钱包（建议与攻击地址一致，或官方认可的映射地址）；  
4. 在授权披露前不擅自公开完整利用细节（§7）。

**发放：** 主网上线并公布 TGE / 空投规则后，按公告汇率发放 **约 1,000 USDT 等值 TTS**。

| 情形 | 轨 B |
|:--|:--|
| 仅轨 A，未开 / 复现不全 | **不发** |
| 轨 A + 合规 Issue | **发放** 约 1,000U 等值 TTS |
| 仅 Issue，无轨 A | 走 **轨 C**，不是 B |
| 同一根因多名轨 A 成功者 | **首次确认且完成披露**者获轨 B |

轨 A 与轨 B **可叠加**：先拿靶场结算，上线后再拿 TTS 空投。

### 3.3 轨 C · 其它有效报告（按等级 TTS 空投）

面向**未达成轨 A**（或不申请 A）的有效报告人，以及经认定的协作验证者。建议等值档（**以最终公告为准**）：

| 等级 | 建议等值（USDT） | 典型影响 |
|:--|:--|:--|
| **Critical** | 500 | 抽干资金、无限铸币、永久冻结用户资产等 |
| **High** | 200 | 大额可盗、权限抢占致资金风险、严重经济操纵 |
| **Medium** | 100 | 有限损失、可利用会计错误、资金路径 DoS |
| **Low** | 30 | 苛刻前置、局部问题、有限配置滥用 |
| **Informational** | 0～可选小额 | 最佳实践、文档、无直接利用 |

- 不可重复领取：已获轨 B 者，**同一根因**不再拿轨 C Critical。  
- 协助独立复现 / 验证者，经 Issue 确认后可获同档或降一档较小额度。

## 4. 等级与有效性

| 等级 | 定义要点 |
|:--|:--|
| **Critical** | 直接盗取 / 不可逆重大资金损失；无限铸 TTS；伪造 proof 份额等 |
| **High** | 重大资金损失或关键权限（已泄露 Admin 私钥类默认不在范围，除非合约本身导出密钥） |
| **Medium** | 中等经济影响或资金相关路径功能破坏 |
| **Low** | 影响有限、条件苛刻 |
| **Informational** | 无直接利用路径 |

**首次有效**（以官方确认为准）就同一根因获奖。已知问题、无 PoC 的纯理论、未获轨 A 却申领轨 B 的，驳回或降级。争议由 TTSWAP 安全对接裁定，必要时第三方复审。

## 7. 规则与 Safe Harbor（草案）

1. 仅针对本期授权地址。  
2. 不得破坏公共基础设施或攻击无关用户。  
3. 优先 GitHub（或指定私密渠道）；授权前不得公开完整利用代码。  
4. 轨 A 以证明可利用为限；保留可追溯记录；若公告要求，结算前将抽出资金转回指定地址。  
5. 不得勒索；不得冒充 TTSWAP。

**Safe Harbor（草案）：** 在遵守本计划与适用法律的前提下，对**授权范围内**的善意安全研究，TTSWAP **不主动**仅因此提起民事诉讼。不在范围内：未授权目标、靶场外第三方损害、勒索、违法行为。

## 9. FAQ

**抽干靶场后还要不要开 Issue？**  
要 — 若想拿 **轨 B**。轨 B **只给**完成完整 Issue 的轨 A 成功者。

**只写 Issue、没打成，能拿 1,000U 轨 B 吗？**  
不能。走 **轨 C**。

**能否按尚未注入的 4,000U 总额要求结算？**  
不能。轨 A 只认**确认时链上真实剩余**。

**期中池子空了怎么办？**  
轨 A 暂停，直至下一批约 1,000U 或重部署。已确认轨 A + Issue 仍可在上线后拿轨 B。计划上限仍为 **4,000U**。

**可以匿名吗？**  
可以，但须留下可送达的奖励地址。
